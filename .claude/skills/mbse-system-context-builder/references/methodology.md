# MBSE System Context Methodology

## System Boundary

Definition of what is inside vs outside the system. Critical for scope management.

Elements:
- System name and abbreviation
- Clear boundary statement
- Exclusions and assumptions about environment
- Operational domain (environment, geography, constraints)

## Actor Inventory

All external entities that interact with the system.

Types:
- Human actors (drivers, operators, users)
- System actors (other systems, hardware, software)
- Environmental actors (nature, weather, regulatory)

## External Interfaces

Points of interaction between system and actors.

Characteristics:
- Identified per actor relationship
- Clearly directed (in, out, in-out)
- Typed by medium (data, control, energy, material)
- Allocated to system functions later

## Use Cases

Actor-centric descriptions of system behavior.

Structure:
- Primary actor (initiates use case)
- Secondary actors (participate)
- Preconditions, main flow, postconditions
- Alternative and exception flows

## Stakeholder Needs

High-level expectations and constraints.

Levels:
- Strategic (business, mission)
- User (how people will use it)
- System (constraints, regulations)
