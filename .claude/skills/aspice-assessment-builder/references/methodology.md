# ASPICE Assessment Methodology

## Overview

ASPICE (Automotive SPICE) Process Assessment Model (PAM) v3.1/v4.0 defines a reference framework for assessing the capability of software and system development processes in the automotive industry.

## Capability Levels

### CL0 - Incomplete
Process is not implemented or fails to achieve CL1 performance.

### CL1 - Performed
Process is executed. Base practices are performed and work products are produced. No formal management exists.
- **Requirement**: PA1.1 (Performance) >= L (Largely achieved)

### CL2 - Managed
Process execution is managed with defined goals and managed work products.
- **Requirements**: CL1 achieved + PA2.1 (Performance Management) >= L + PA2.2 (Work Product Management) >= L
- **Key Practices**: Process goals defined, resources allocated, work products tracked

### CL3 - Established
Process is formally defined and deployed across the organization as a standard.
- **Requirements**: CL2 achieved + PA3.1 (Process Definition) >= L + PA3.2 (Process Deployment) >= L
- **Key Practices**: Standard process documented, tailored for projects, training provided

### CL4 - Predictable
Process is controlled and optimized based on quantitative metrics and data.
- **Requirements**: CL3 achieved + PA4.1 (Measurement) >= L + PA4.2 (Control) >= L
- **Key Practices**: Metrics collected, process controlled, statistical trends analyzed

### CL5 - Innovating
Process is subject to continuous improvement and innovation.
- **Requirements**: CL4 achieved + PA5.1 (Innovation) >= L + PA5.2 (Optimization) >= L
- **Key Practices**: Improvement ideas generated, pilots executed, lessons learned captured

## Assessment Process

### Phase 1: Planning
- Define scope (process areas in scope)
- Select assessor and assessment team
- Schedule assessment activities
- Identify evidence sources

### Phase 2: Data Collection
- Conduct interviews with process owners and practitioners
- Review work products and project records
- Examine process documentation
- Collect metrics and performance data

### Phase 3: Indicator Rating
- Rate each base practice indicator: N/P/L/F
- Rate each generic practice indicator: N/P/L/F
- Document evidence and rationale

### Phase 4: Process Attribute Rating
- Aggregate indicators to rate PA1.1, PA2.1-2.2, PA3.1-3.2, PA4.1-4.2, PA5.1-5.2
- Rating aggregation rules per ASPICE PAM

### Phase 5: Capability Level Determination
- Apply CL determination algorithm
- Document CL per process
- Identify strengths and weaknesses

### Phase 6: Report and Follow-up
- Prepare assessment report
- Present findings to sponsor and team
- Identify gaps and improvement opportunities
- Plan follow-up assessments

## Evidence Types

### Work Product Evidence
- Specifications, designs, code
- Test plans, test results
- Reviews records (code reviews, design reviews)
- Documentation

### Process Performance Evidence
- Project plans and tracking
- Action logs, defect logs
- Meeting minutes
- Resource allocation records

### Quantitative Evidence
- Metrics: cycle time, defect rate, schedule performance
- Trends and analysis
- Process control charts

### Process Definition Evidence
- Process documentation
- Standards and guidelines
- Templates and checklists
- Process deployment records (training, communication)

## Assessor Qualifications

Assessors should be:
- Trained in ASPICE assessment methodology
- Certified by intacs (International Automotive Competency Specification)
- Experienced in software and system development processes
- Familiar with automotive industry context

## Common Assessment Challenges

1. **Evidence Gaps**: Insufficient documentation or artifact access
   - Mitigation: Pre-assessment planning to identify evidence sources

2. **Process Maturity vs. Documentation**: Organizations may practice well but document poorly
   - Mitigation: Interview-based evidence collection, not just artifact review

3. **Process Tailoring**: Processes must be tailored to project characteristics
   - Mitigation: Assess tailoring mechanisms and deployment approaches

4. **Organizational Variation**: Different teams may implement processes differently
   - Mitigation: Sample multiple projects and teams

5. **Assessment Timing**: Timing affects which work products are available
   - Mitigation: Plan assessment after key project phases to access evidence

## Success Factors

- **Sponsor commitment**: Executive support for assessment and improvement
- **Team cooperation**: Active participation in data collection
- **Evidence preparation**: Pre-assessment evidence organization
- **Clear scope**: Specific processes and projects in scope
- **Realistic expectations**: Understanding that assessment is baseline, not prescription
